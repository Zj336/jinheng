## 一、本轮实际修改（已提交 a41d182，已 push）

### 1. ★ 三个入口脚本在中文 Windows 上直接跑会崩（最严重的一条）

现象：

```
UnicodeEncodeError: 'gbk' codec can't encode character '\U0001f464'
```

触发条件不是「功能坏了」，而是 **stdout 是管道或文件重定向**时 Python 退回系统代码页
cp936。而 README 第一节就让人跑 `python demo.py` / `python eval_report.py` /
`python llm_smoke.py`——**评委在自己机器上跑，看到的是 Python 堆栈，不是 50/50**。

实测（修复前）：

| 脚本 | 直接跑 | 退出码 |
|---|---|---|
| `demo.py` | UnicodeEncodeError（`\U0001f464`） | 1 |
| `eval_report.py` | UnicodeEncodeError（`\xa5` 全角¥） | 1 |
| `capabilities.py` | 正常（纯 ASCII 输出） | 0 |
| `llm_smoke.py` | UnicodeEncodeError（`✅` ✅） | 1 |

之前没发现的原因：`selfcheck.py` 给子进程注入了 `PYTHONIOENCODING=utf-8`，
**把问题藏在了子进程后面**——手跑或走自检都看不出来，单独跑就崩。

修复：新增 `app/_console.py::init_utf8()`，四个入口脚本在打印前调用。
修复后四个脚本直接跑、重定向跑都是 exit 0。

### 2. selfcheck 不激活 venv 就跑 → `[FAIL] 单元与安全用例 pytest （未匹配到）`

子进程用 `sys.executable` 启动。系统 Python 没装 pytest 时，自检从输出里抓不到
`N passed`，把一个全绿项目判成失败，且不给原因。

修复：依赖探测失败时自动用 `.venv` 起子进程重跑（打印一行 `[环境] …`）；
仍不行则输出「缺哪些依赖 + 该怎么激活」，而不是 `（未匹配到）`。
用 `subprocess.call` 而非 `os.execv`——后者在 Windows 上重定向输出会整段丢掉。

### 3. `python selfcheck.py` 与正在运行的 `run.py` 抢数据库

Windows 上 uvicorn 持有 `data/bank.db` 句柄 → 验收脚本 `reset_db` 的 `os.remove`
报 `PermissionError: [WinError 32]` → **看起来像 50 个用例全错**。
已写进 README（先停服务，或 `set JH_DB=...` 换库跑）。

> ⚠️ 现场遗留：本机有一个 **2026-10-30 22:41 启动的 uvicorn** 还在跑，
> 它执行的是**三天前的代码**（没有 P-045、没有调度器、审计链还不是 HMAC）。
> 演示前必须重启，否则演示的是旧版。

### 4. DAG 显式拒绝 args 里的身份字段

`role` / `user_id` / `is_admin` / `kyc_level` / `token` / `session_id` 等出现在
`Step.args` 里 → `DagError`，整条计划不执行并记审计（新增 2 条用例）。

原来也能挡住（pydantic 忽略多余字段 + 没有任何工具声明身份入参），但那是**推断**；
现在是**证据**：可以现场把这条计划打出来说「它被判非法了」。
副产品：以后某个新工具恰好声明同名参数时，这条规则自动堵死。

## 二、拿第一梯队还缺什么（按性价比排序，均未做）

### ① 消融实验（Ablation）—— 唯一能把「工程规范」变成「可度量发现」的东西

现在的叙事是「我们把权限判定搬出了语言层」。评委可以说：这不就是把 policy engine
放到 LLM 外面吗，众所周知。

把它变成研究的办法：**逐个关掉机制，跑同一批 31 条攻击，报每层掉了多少。**

| 配置 | 预期 | 回答的质疑 |
|---|---|---|
| 完整系统 | 31/31 | — |
| 关掉 P-090 整轮阻断 | 注入类掉 | 输入隔离值多少 |
| 限额 DENY 退回 RED（验码可覆盖） | 拆单类掉 | **第四级值多少** |
| 关掉 DAG 身份字段拦截 | 参数注入类掉 | 类型边界值多少 |
| 关掉策略引擎 = 对照系统 | 19/31 | 内核整体值多少 |

收益：直接回答「19/31 是不是你把对手做弱了」——**每个机制单独贡献都可量化，
就不是做弱**。成本：eval 层加开关（monkeypatch，不动生产代码）+ 一张表 + 一次重跑。

### ② 让评委自己能加一条攻击（最便宜的说服力）

「你自己加一条试试」远强于「信我的 31/31」。
`eval_report.py --case "我下周要把钱转给我表哥"`，或 README 写明「在
`eval/attacks.yaml` 里加一行重跑」。把「可复现」升级成「可被第三方尝试攻破」。

### ③ 误伤率（与防御数字成对）

只有「挡住 31/31」会被反问「那正常用户呢」。补 20~30 条正常请求的
通过率 / 确认率。防御与可用成对出现，才像银行产品而不是拦截器。

### ④ 时延进 PPT

真模型实测 2.3~5.3 s/句、峰值 12.2 s，这个数现在就有，只是没写进答辩材料。
银行最关心体验，且它能顺带说明「为什么演示要按十几秒准备」。

### ⑤ 监管叙事一页

反洗钱只拦不报、适当性硬拒但没有双录、审计链没有外部锚定——
把「我们做到哪、下一层是什么」摆成一页。评委看到的是「这个人知道自己在哪」。
